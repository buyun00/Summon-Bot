# Bot 3+3：可观察行为与边界

更新：2026-11-02。这是第二版源码对应的行为说明，供自然使用时理解真实状态；不是测试脚本、上线门禁或要求向生产发送样例任务的验收清单。

| 场景 | 当前实现表达的行为 | 不能据此声称 |
| --- | --- | --- |
| 一个 Bot 承接多个工作 | 每个 work/conversation 独立 Agent，同会话串行，不同工作有限并发 | 所有外部系统都允许同时修改同一资源 |
| 群里委托后私聊更正 | 从 S3 来源与目录查找原 work，沿同 workId 与 MD 续接 | 根据最后活跃项猜测归属就是正确路由 |
| 新人类群消息没有 @ | 明确引用/归属直接定位，否则一个普通成员做一次只读语义路由 | 全体成员都已阅读、同意或受托 |
| 当前用户停止、取消或纠正 | 当前原文立即进入业务上下文；停止状态保存，迟到事件不自动恢复 | 外部取消受理代表所有副作用已停止 |
| 等待同伴或 Codex | work_wait/外部绑定持久保存，本段结束释放执行位 | 消息已投递或得到 taskId 就是目标完成 |
| 同伴失败、取消、中断 | 真实终态沿原关联回流，负责工作判断下一步 | 失败后可以不查未知副作用就重发 |
| 整理知识与 Skill | 新短暂对话读取相关旧 MD/来源，保存后前移游标，允许无变化 | 每段对话都必须产生一份 Skill 或新知识 |
| 组装上下文 | 新短暂对话按需读取并输出本次临时输入 | 组装输出成为新的事实证据或永久知识真相 |
| 压缩或重启 | 保留 S1、稳定 work、外部操作与未知结果，按安全边界续接 | 可以复制已发出的任务或重放已执行工具 |
| 维护失败 | 旧 MD 与待整理位置保留，错误可见 | 失败批次已经整理或输入一定能容纳 |
| 连接器断线/游标缺口 | 查询已知快照、保留可见缺口、沿原操作键恢复 | 未返回历史等于工作未执行或已成功 |
| 定时职责没有新状态 | watch 只读观察、不唤醒模型；在途同职责合并 | 任意外部业务来源都已实现无需模型的探测 |
| 重复互聊 | FYI、纯致谢、完全重复无新来源链停止；工作仍保留 | 正常长任务到固定轮数或时长后必须结束 |
| 自动通知 | 持久记录通知，按同 ID 投递原授权目标 | 已发出意味着真人已经看见 |

原始消息、工具结果和当前 S3 分别说明“说过什么”“实际做了什么”和“现在负责什么”。Markdown 总结用于导航与恢复；关键事实应回到来源，不把总结中的完成字样当作执行事实。

正式地址与数据根不变。未自然观察的多工作并发、真实模型整理、连接器恢复、群聊语义选择等行为，应在交付说明中如实标明。它们不是要求补跑测试、制造生产聊天、计算哈希或增加证据包的理由。
