# 前台聊天与独立工作

同一个 Bot 保留身份、职责与方法，chat、work、maintenance 分开上下文和工具权限。前台只聊天、查询资料与协调任务；实际制作始终在独立 work 或该 work 绑定的 Codex 中进行。

## 权限

运行时按持久化 task 的 workId 判定模式，不能由模型参数声明执行权限。

| 范围 | chat | work |
| --- | --- | --- |
| 文件读取、搜索、网页搜索与读取 | 针对性查询，输出有上限 | 按工作需要查询 |
| 项目文件写入、编辑、命令、构建、部署和业务写入 | 禁止 | 依角色授权执行 |
| 新建工作、送达用户纠正、暂停和取消 | 前台协调 | 只维护自身工作 |
| 用户房间消息与聊天回复 | 前台处理 | 不读取消息流，不直接发言 |
| 执行日志与完整过程 | 不自动回流，仅查询简短状态 | 保留在自身 work、S1 和产物 |
| 能力目录调用 | 内层工具必须为 read | 依已配置能力执行 |

角色工具配置表示 Bot 可使用的能力总集，不能代表一次聊天执行的权限。引擎过滤工具声明并在每次调用前检查；网关从运行时请求头取得 taskId，读取该 Bot 的真实任务，再执行同一策略。模型提供的上下文字段不能提升权限。Bot 凭据不能调用用户管理 API。

web_search 和 web_read 是独立的只读查询工具，不通过 shell、脚本、表单或浏览器执行网页代码。MCP 按显式 toolEffects、配置的 effect 或服务声明的 readOnlyHint 识别查询；未明确为只读的工具须交给 work。

## 交接与结果

前台先查已有 work。制作请求通过 work_create 交接自包含的目标、要求、必要输入与授权；纠正通过 work_dispatch 送到原 work。交接成功后立即结束前台当前执行段，后续聊天可继续接收新消息。同一前台任务重复创建工作时复用已保存的交接，同一派发事件保持幂等，不再出现聊天和 work 同时制作。

用户在房间发来的消息始终先到前台。即使回复关联了已有 work，也由前台判断是查询、讨论、纠正还是停止，再做协调。worker 收到的是明确的工作输入，不是整段房间对话。

worker 记录自身进度和终态，work_notify 只向原授权来源返回有长度上限的结果。房间结果先进入前台同一聊天的 work_result 事件，前台转达，运行时持久投递并去重；worker 不直接在房间发言。能力维护者委托也通过独立 work，不通过聊天 DM 承接制作。

## 上下文

chat 与 work 只读取自身会话原文；work 不读取来源聊天。前台任务查询返回简短状态，不返回任务输入、工具记录或完整执行结果。聊天查询的大块返回有上限，需要缩小范围或交给独立调研工作。

Markdown 的发现、组装和整理遵循同样边界：chat 不读取 work 总结，work 只读取自身总结；通用可复用方法通过 Skill 使用。旧原始记录继续保留，新策略首次启用时不将旧执行历史直接装入活动上下文；旧总结按本范围的投影重新整理，聊天投影排除制作工具与调用过程。原始聊天、用户文件、有效记忆来源和工作记录不删除。
