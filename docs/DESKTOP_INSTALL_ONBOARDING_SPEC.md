# Summon Bot 单包安装与欢迎引导改造

## 交付范围

Windows x64 和 Apple Silicon Mac 分别发行一个 Summon Bot 桌面安装包。每个包包含对应平台的 Node 运行时、服务端和生产依赖、Web 页面及 Electron 外壳。复用现有服务端构建、安装、启停和应用签名身份，按同一源码提交生成桌面包。

Web、Windows/macOS 桌面、iOS、Android 继续组成四类终端。Web 与 Electron 使用所连接实例提供的同一套页面，iOS 与 Android 使用现有原生界面和 API。后端部署机负责运行 Bot、存储数据和接入本机工具。现有实例可以使用本机回环、Cloudflare Tunnel 或 Tailscale Serve。远程访问设置可在引导中跳过。

现有正式实例继续使用 `D:/Relay-Bot-app`、`D:/Relay-Bot-data`、`http://127.0.0.1:8787` 和 `https://bot.lin0.org`。在该实例创建的工作区使用相同的服务与数据根。实例保存其访问配置、会话、记忆、工作和文件。

## 安装包与运行模式

| 操作 | 应用行为 |
| --- | --- |
| 首次打开 | Windows 安装后打开 Summon Bot，在开箱页选择本机正式实例或远程地址。新建或选择工作区后，在同一窗口的正式页面配置聊天模型和凭据。 |
| 在本机使用 | 使用 `D:/Relay-Bot-data` 和原有回环入口。桌面连接现有正式服务，工作区保存于该实例。 |
| 通过地址连接实例 | 填写实例地址并提交访问令牌，随后新建或选择该实例的工作区。 |
| 更换连接 | 在应用内选择实例和工作区，保存已连接的地址。各实例保留自己的工作区数据。 |
| 关闭窗口 | 部署主机继续运行服务，启停由正式安装入口管理。 |
| 安装升级 | 客户端沿用应用身份和连接配置。正式服务按现有安装流程切换当前发行，沿用业务数据和访问令牌。 |

桌面应用保存用户选择的连接。连接地址属于运行配置，客户端发行来源属于发布配置。更新优先使用设备本机发行物，本机缺少时查询 GitHub Releases。桌面 IPC 和导航限制跟随用户选定的实例。远程网页通过当前实例的登录和 API 使用工作区。安装包、命令输出和调试记录中只出现脱敏状态。

打包复用 `scripts/build/build.mjs`、`scripts/installation/` 和 `desktop/build.mjs`。内置后端和 Node 放入独立运行资源，供操作系统启动。Node 及生产依赖跟随目标平台和架构，业务数据保存在可写目录。macOS 发行继续使用现有 Developer ID 和公证流程，内置可执行文件一并纳入。GitHub Actions 从同一提交构建发布各平台，Windows 本机包沿用本机发行目录。制作和独立验证期间先提供候选产物，正式环境部署与正式发布遵守现有定稿流程。

## 欢迎 Bot

在设置中保留可再次进入的「新手引导」。已完成配置的工作区打开时直接进入工作台。新装未配置、用户主动重开引导或当前步骤等待授权时恢复对应进度。

1. **模型连接引导。** 在所选实例的新工作区进入脚本对话。用户选择 API 提供商、协议、地址及模型，再用隐藏输入保存 Key，也可以选择订阅授权或导入部署主机上的登录。模型连接由服务端保存，脚本消息与凭据各自走对应的存储入口。
2. **在私聊中配置。** 聊天模型保存后，主 Bot 的引导消息直接写入现有私聊。每个步骤只追加一条实际要问的问题，当前选项附在对应消息里。刷新、双击和重启沿用已保存的步骤及消息。
3. **发现并接入本机工具。** 主 Bot 发起 Pi 初始化工作，从部署主机的 PATH、安装位置和项目入口发现 CLI。登记后的维护 Bot 读取版本和帮助，保存可用方法与来源。引导按实际发现、可用方法和等待状态汇报进度。
4. **再配置远程访问。** 工具发现步骤结束后，主 Bot 询问是否从其他设备访问。用户可以选择只在本机使用，或按私网和公网需要配置 Tailscale Serve 或 Cloudflare Tunnel。入口和错误提示出现在对应的引导消息中，密钥留在受控输入里。

引导使用独立的 Pi 工作处理工具发现及用户确认的远程设置，用固定的步骤工作 ID 接收重试和补充。`workspace_setup` 处理当前步骤的工具发现进度或授权的远程设置。工具能力登记在共享目录，远程配置沿用工作区的现有设置和权限。

远程方案可由用户在聊天中直接描述，也可选择临时入口。Pi 可通过 `start-remote` 启动内置 Cloudflare Quick Tunnel，或传入自己编写的 Node 桥接脚本及参数。脚本从 `SUMMON_WEB_URL` 读取本机目标，在入口就绪时通过 IPC 返回 `remote-ready` 与 HTTPS 地址。服务管理器接管其进程树、停止和重启，地址经工作区探测后登记。已有外部代理可使用 `register-remote` 登记。网页在 SSE 连接不可用时轮询同步，供临时隧道使用。

Web 与原生端共用后端引导状态和现有模型接口。优先整理网页行为，再同步 iOS 和 Android 的对话式连接、进度和可跳过步骤。已保存的手机连接继续可用，新装优先填写用户自己的地址。iOS 切换服务时处理旧服务离线或令牌失效，避免旧推送注销阻断新工作区连接。系统 VPN、Codex 及供应商授权仍使用各自的用户确认界面。

## 原生工具与原工作

Codex 和其他 CLI 通过能力目录接入。Pi 根据已登记的方法，在当前授权的项目目录执行。工具使用部署主机的登录和配置，工作中的授权或输入请求可经工具事件返回原对话或工作详情。

受管执行关联原工作、操作标识和实际工具。工具提供原生会话标识且存在适用的续接方法时，可以在原 WORK 继续。首次升级时保留已有工作的进度、历史、产物和暂停意图。原会话或操作结果待确认时，先查询实际状态再决定下一步。

维护 Bot 也可发布实际观测的工具额度、状态和进度。聊天模型与工具展示来源沿同一组后端接口返回。[能力目录与共享 Skill](CAPABILITY_CATALOG.md)

## 两种远程入口

同一实例可以保留本机回环、已配置的 Cloudflare 地址和已配置的 Tailscale 地址。扩展现有 `publicOrigin` 的单地址模型时，把当前值一次性迁入生效的远程配置。Web 登录、Cookie 与跨源检查匹配用户访问的已登记 HTTPS 地址，匹配经过规范化的协议、Host 和端口。继续使用现有工作区令牌，代理保持原始 Host 并实时转发 `/api/stream`。远程入口转发 Web，网关、控制端和工具进程在部署主机上运行。

| 入口 | 对话可做的配置 | 外部条件 |
| --- | --- | --- |
| Cloudflare Tunnel | 复用已配置的公开 HTTPS 主机名和 `cloudflared`，确认本机目标 Web 端口。对于用户选择由 Summon 管理的连接器，收集已建隧道的凭据，使用私有令牌文件或官方支持的私有配置启动，查询连接状态。 | 用户拥有或获准管理域名和隧道，已发布主机名，部署机的 `cloudflared` 可以连接 Cloudflare。 |
| Tailscale Serve | 检测部署机的官方 Tailscale 客户端、登录和 Serve 状态，用户确认后为本机 Web 建立一条私网 HTTPS 转发，把分配的 `https://…ts.net` 地址加入实例配置并提供给用户。保留已有 Serve 映射。 | 用户完成登录与私网 HTTPS 授权，手机或另一台电脑加入该 tailnet 并有访问权限。 |

Tailscale 首版复用系统已安装的官方客户端及 Serve，缺失时提供官方安装和授权指引。桌面包包含接入引导和配置操作。保留现有 Cloudflare 正式配置的归属，新增远程设置由使用者操作自己获准管理的资源。对非本应用创建的外部隧道及 Serve 映射采用查询和复用。应用自行管理的转发以明确的目标、端口和归属记录精确启停。

本地网络变更经用户确认后由桌面本机控制层或安装后的本机 CLI 执行，提供查询、准备、应用和撤销该条配置的结果。反向代理也可能连到回环，不能仅以请求源地址判断控制权限。模型工具的操作范围绑定本次确认的配置动作。访问令牌、供应商 Key、隧道凭据和外部授权不进入普通消息、源码、工作日志或验收记录。

参考 [Cloudflare Tunnel 配置](https://developers.cloudflare.com/tunnel/get-started/) · [cloudflared 令牌文件](https://developers.cloudflare.com/tunnel/reference/run-parameters/#token-file) · [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve) · [Serve CLI](https://tailscale.com/docs/reference/tailscale-cli/serve)。

## 程序化操作与验收

程序化操作使用安装 CLI 的 `init/start/status/stop`、Web 访问认证、`/api/state`、`/api/model-settings/onboarding` 及其 `reply/start/advance`、模型连接、工具目录、原工作接口、聊天和 SSE。桌面安装后的 `summon status` 可查询版本和连接状态。程序化方式沿用界面使用的校验、状态、权限和执行逻辑。

程序化操作可查询已安装版本和连接模式，按步骤驱动引导，查询、确认及应用远程配置。正式服务启停和查询使用正式安装入口。原单包方案的验证入口包括安装后的程序、CLI、HTTP/SSE、进程和系统安装工具，可用 `adb` 或 `simctl` 做程序化安装和启动。

候选产物从制作对话提供的同一版本取得。首次安装、升级与失败分支用按次释放的 Windows 和 macOS 验证主机或 CI runner，结束后停止受管进程并清理本次验证的安装。当前正式主机不另起并行验证服务、不替换生产数据、不改现有域名或私网设置。受控模型服务可以用于可重复的引导验证，须让真实的 Pi 请求、响应和工作记录走正式链路。实际第三方登录、域名或权限要用已授权资源，报告时区分受控替身、实际网络验证及缺条件的项目。

下表记录单包方案的验收范围。实际验证覆盖以该次发行授权和记录为准。

| 验收项目 | 操作与判定 |
| --- | --- |
| Windows / macOS 安装 | 安装候选 EXE 或 DMG，打开应用进入实例和工作区选择。检查升级后所选实例、既有会话和私有配置。 |
| 两种连接模式 | 本机选择连接正式回环入口。远程使用指定实例地址和访问令牌。连接后均可在应用内创建或选择工作区。 |
| 欢迎 Bot | 新实例可操作脚本对话并配置模型，模型不可用可返回更改。首条真实回复来自实际 Pi 路径，房间与进度在重启后续接，重复操作不生成重复会话。检查返回内容和聊天数据不包含输入秘密。 |
| 原生工具 | 记录发现入口、版本、维护 Bot 和方法。工具具备使用条件时，经原工作执行并读取实际状态、会话标识和结果。按实际运行平台和账号权限记录覆盖范围。 |
| Cloudflare 与 Tailscale | 走程序化本机操作，覆盖外部组件缺失、未授权、已配置复用和授权成功路径。两个已登记 HTTPS 地址分别验证登录、API 和实时 SSE，额外 Origin 被拒绝。真实隧道或 tailnet 的验证按实际授权资源记录。 |
| 四端 | Web 与桌面连接同一工作区。iOS 和 Android 使用自定义地址和令牌并完成相同引导与状态读取。记录真实设备、模拟器或协议层各自覆盖的范围，旧端地址不可达时检查可重新连接。 |

验证对话把一轮所有可运行项执行完，再记录每项的候选版本、实际操作、结果与可复现问题，区分通过、失败和外部条件缺失。每次修复后基于新候选重新验证受影响路径及完整安装链。依据实际结果判断完成。

## 原单包改造的交接顺序

1. 新建 `gpt-6.1-sol`、`max` 制作对话，创建 Goal 承接本改造。由该对话负责代码、接入、构建、修复和后续验证调度。共享工作区已有独立改动，交付只包含本任务范围。
2. 制作对话完成实现并给出可供安装的候选产物后，新建 `gpt-6-astra`、`max` 验证对话。验证对话独立执行完整的程序化安装验收，将一轮结果和问题留在 Markdown，完成整轮后交回原制作对话。
3. 制作对话根据问题记录修复，准备新候选并交给验证对话复验，直到安装和功能验收没有未解决的问题。外部账号、凭据或设备条件缺失时列明具体项目及实际缺项。用户请求的安装验证按本节执行，仓库其他测试、哈希和额外验收约定继续遵守。
