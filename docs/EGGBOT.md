# EggBot 与群聊团队

EggBot 是可复用的系统 Bot，负责按项目需要组队、成员生命周期、交接及协作改善。每个普通群默认包含主控与 EggBot；主控优先采用创建群时选定的首位可用成员，无其他成员时使用入口伙伴。私聊与独立深聊保持原用途。

用户的新群消息由明确的工作或回复关联、点名确定承担者，未明确时由当前主控接住。其他可用成员合并观察已公开的实质增量，读取范围限于本群。自动和持续项目群从第一条实质消息起可以评估分工，日常交流群不自动组队。

有已登记专职成员的项目中，无明确归属的新议题先按现有职责选择一个收件人；无法确定时仍由主控接住。已指派专职的成员收到与自己责任相连的定向讨论、回复或工作，避免给所有专职成员泛发普通观察。

## 每位工作 Bot 的协作判断

所有角色及已登记能力的维护者可以从自身职责提出有来源的协作问题，包括范围、依赖、时间、重复劳动、反复返修、无人承接和能力缺口。判断依据是用户原目标、当前要求和实际工作，不能用进程存活、回执数量或代码修改量代替交付推进。

成员可直接查证和提出替代方法，也可在群里联系相关成员或 EggBot。只有实质增量才发起讨论，不强制每轮反思，不群发试探，不以投票代替证据。意见送达和实际解决分别记录。

## 工具

| 工具 | 用途 |
| --- | --- |
| `chatroom_team_read` | 读取共享目标、要求、期限、主控、成员、工作状态、开放问题、角色能力和本群自动职责情况 |
| `chatroom_team_raise` | 任何成员提出协作问题，持久记录来源，并投递给 EggBot、主控或明确指定的本群成员 |
| `chatroom_team_manage` | EggBot 管理成员和交接；主控也可调整责任、维护项目和结清问题 |

管理动作：

- `assess`：在当前分工任务中登记行业、阶段、交付链和有证据的候选。可以没有候选，也可以有多项自定义职责。
- `create`：真实需要独立成员时，创建项目职责对应的临时 Bot。可选用已有角色模板。评估创建的成员使用自己的工作区和本群协作能力，不授予项目目录、命令、外网或连接器。
- `invite`：邀请已有可用成员；不会复制身份、记忆、凭据或私聊。
- `assign`：调整本项目责任，并通知原成员沿已有 work 继续。
- `close-duty`：按当前阶段结束证据结清原职责，停止按它分流。成员、工作和已发产物仍可按原权限查阅。
- `promote`：根据独立长期维护对象、持续需求和复用价值，将成员升级为常驻。
- `resume`：明确恢复休眠/暂停的普通成员；后续可邀请参与当前项目。
- `leave`：结清或交接本群工作后退出；不影响其他项目。
- `retire`：临时成员没有其他团队、未完成工作或未知外部执行时进入休眠；保留所有有效数据。
- `handoff`：让本群现有可用成员接替主控。`stopCurrent:true` 先暂停旧主控在本群的指定 work/执行并请求中断原外部回合；未知或仍在停止时保持待交接，由服务继续核对，停止状态已知后通知接替者。其他群与私有工作不被取消。
- `project`：维护目标、要求、状态、期限、下次复核时间和周期。
- `resolve`：记录实际处理结果，结清协作问题。

管理和提问都使用稳定 `operationId`；管理动作要求 `reason`，可引用当前群的 `sourceMessageId` 和读取到的 `expectedRevision`。结果不明时沿原操作与外部绑定查询，不换键重发。

项目分工判断使用当前修订号和原始消息。按同一项目、负责对象和职责边界识别同一责任，`dutyKey` 与 Bot 的显示名称分开。重试原来源沿原评估与管理操作；新证据可更新判断。先核对现有成员的职责、能力、状态和授权，再沿用、指派或邀请。入群和指派有实际定向投递，分工本身不批准新制作。

每个候选说明负责对象、边界、完成条件、参与时机和后续要保留的材料。一次性事项优先现有成员或独立 work。只有明确的持续责任，或现有成员另开 work 会损失具体的独立判断、并行或维护收益，才登记独立成员。实际使用和维护的对象从项目交付链发现，不按项目类型填一张固定岗位表。

## 项目检查点与改善

持续项目设为 `active`，普通交流使用 `idle`。新建或编辑群聊时可直接选择持续项目并填写目标。自动识别使用已保存的群目标和同一项目至少两条不同的已授权群来源。可以登记 `deadlineAt`、`nextReviewAt`、`reviewIntervalSeconds`（默认 900 秒）和 `auditIntervalSeconds`（默认一周），周期最短 60 秒。

到了检查点，有新增实质交流或已到登记期限才复核。同一检查未结束时合并，复核回复保留在群中。项目 `paused` 或 `completed` 后停止项目复核，显式恢复后按当前目标继续。

分工评估使用实质用户消息、真实 work 派发或交付，以及有原始来源的协作缺口。已保存的项目先读当前目标、近期原文和实际交付，新项目可以当轮判断。定期协作复核的启用条件不限制分工判断。评估只读本群材料和可用成员，动作通过原团队管理流程落实；没有调整时只保存依据。

网页的群聊详情可展开“项目分工”，查看负责人、当前状态、需续用的资料及已发布产物。职责保存同群原始消息和工作引用；后续接手时仍按实际权限读原件。结清阶段或完成项目后，旧职责保留供接续查阅，临时成员可沿原生命周期休眠。

旧数据中的 EggBot 若已停止，升级不会自动重启。可在网页选择 EggBot 并直接发送一条请求；如果成员已暂停，先用原有的“恢复 Bot”入口。新安装的默认 EggBot 可在首次实际分工时启动。

EggBot 可按需读取本群原文，从反复用户纠正提出补方法、Skill、调整分工或增补成员的方案；定期结合真实职责、在途项和报告的调用量审视空转。没有可行动贡献保持安静。跨群复用身份不会使某群获得其他群或成员私聊的内容。

角色、提示词和 Skill 表达预期行为；不能据此宣称模型已被证明能够稳定识别偏航。运行事实、实际产物与模型行为分别报告。

## 网页接口

- `GET /api/rooms/:id/team`
- `POST /api/rooms/:id/team/raise`
- `POST /api/rooms/:id/team/manage`

沿现有正式网关和网页使用，不新增服务、端口或数据根。EggBot 的公开头像、成员详情和对话使用现有 Bot 界面。

参考：Grok 官方 [Dr. EggBot](https://x.ai/bot/marketplace/bots/dr-eggbot-v2) 的公开创建流程、对话复核和自动职责审视；本项目独立实现入群、临时/常驻、退出及主控接替。
