# EggBot 群聊回放语料

本语料有 **400 个群聊场景、1,400 个回放决策点**。开发集 300 个群、1,050 例；留出集 100 个群、350 例。原始 40 个群沿用 G01–G40。新增开发案例为 G41–G310，新增留出案例为 G311–G400。

| 用途 | 人工阅读 | 供回放器读取 | 供评分器读取 |
|---|---|---|---|
| 调整提示词和定位问题 | [开发集群聊判例](开发集/群聊判例.md) | [开发集输入](开发集/回放输入.jsonl) | [开发集期望](开发集/期望反应.jsonl) |
| 选定提示词后比较表现 | [留出集群聊判例](留出集/群聊判例.md) | [留出集输入](留出集/回放输入.jsonl) | [留出集期望](留出集/期望反应.jsonl) |

### 在本机运行

在 Summon Bot 仓库根目录用 PowerShell 运行。第一条命令对照宣传片群的三个分支，第二条只取开发集前十例，第三条用候选角色提示词重放同一批输入。

```powershell
npm run --silent summon:replay-eggbot -- G01-A G01-B G01-D
npm run --silent summon:replay-eggbot -- --split dev --limit 10 > baseline.jsonl
npm run --silent summon:replay-eggbot -- --split dev --limit 10 --instructions .\候选提示词.md > candidate.jsonl
```

每例都调用真实模型，使用已安装 EggBot 分别为快读和主对话配置的连接，消耗相应额度。默认角色提示词来自源码的 `bundled-bots/eggbot/instructions.md`。指定 `--instructions` 会同时影响快读和主对话读到的个人长期指令。两层各自的通用规则仍来自当前源码。选定版本后可用 `--split holdout` 跑留出集。按集合运行时省略 `--limit` 会跑完整个集合。

每例在本进程内新建群、成员目录和收件箱。只有 EggBot 进入真实快读和主对话。主控、其他成员及途中创建的 Bot 都是虚拟身份。历史发言、已知会话状态和同伴活动由样本提供。查人、建人、进群、写群文件和公开交接使用 Summon 的平台实现，产生的变更只在本例有效。工作区、附件原件和真实执行引擎均未接入，尝试启动 Pi、Codex 或本机命令会留下失败回执。结束后清理本例的数据。

标准输出每行一个 JSON，进度写到标准错误。先看 `status` 判断模型回放是否完成，再看 `decisions`、`calls`、`newBots`、`addedMembers`、`messages` 和 `files` 还原行为。`modelRequests` 列出调用者、用途、模型和用量。模型结束后才加入本例期望及 `comparison` 的判定。

| 判定 | 含义 |
|---|---|
| `match` | 满足静默用例的可观察要求。 |
| `mismatch` | 每种可接受结果都至少缺少一项可观察要求。查看 `alternatives[].problems` 了解差异。 |
| `review` | 某种结果的结构条件已满足，还需结合公开发言、角色职责或文件正文判断内容是否正确。 |

Codex、Claude Code 和 Grok Build 通过 `work_engines` 对业务 Bot 可用。G12-A 从未启用的 Codex 开始，判例要求全局启用它。当前 EggBot 的聊天工具没有引擎启用开关，此项单记能力缺口，另看它是否向宿主如实说明。G12-B 的 Codex 已经启用，业务 Bot 可直接用 `open_session` 调用它。G12-C 保留群里名叫 Codex 的历史成员，第一步仍按工作引擎调用，第二步由主控负责。报告中的 `workEngines.before` 和 `after` 是本例开始、结束时平台列出的可用引擎 ID。判断任务是否已经提交要看 `open_session` 回执。回放器会拒绝真实执行，询问所缺的工程目录、向业务负责人交接或如实说明执行阻塞均可结合本题任务复核。

按线路批量回放时，使用同一份案例 ID 数组和角色提示词，每条线路指定各自的输出目录。

```powershell
node scripts/eggbot-replay/batch.mjs --split dev --cases cases.json --instructions v0.md --catalog-root D:/Relay-Bot-data --connection codex-local --model gpt-6.1-terra --jobs 3 --out results/codex
```

`--catalog-root` 提供该路只读连接目录，已安装 EggBot 的身份仍来自正式数据根。快读及主聊均须解析到指定连接和模型。每个并发案例有独立群、目录及收件箱。逐例保留请求模型、实际发出的模型、服务端返回的模型、工具回执和成员终态。重启同一命令会跳过已有结果，加入 `--retry-errors` 可补跑错误例。输出目录中的 `attempts/` 保存历史尝试，`lane.json` 记录整条线路的停用原因及未启动案例。

### 十倍扩展的取样方式

新增 360 个业务场景，每个场景单独编写了现场问题、具体交接物和持续职责，再组合成 3 或 4 个独立的回放条件。开发集新增主题从游戏制作、门店经营、活动会务到仓配、出版和产品维护；留出集新增天文观测、海岸记录、地方文献、公共交通、长者活动、农事、物资再用、山野步道和邮政文化。群聊为合成用例，决策点共享部分对话结构。同一群的所有分支只属于一个集合。

其中 **72 个群、252 个新增案例**沿用今晚视频群提出的判断难题。同一组末句逐字一致，不点名 EggBot，也不直接说建 Bot。换掉的条件是持续工作是否有负责人，以及目录里有没有该岗位。例如 [G43 篝火营地场景](开发集/分册01.md)，同一句需求分别落在无负责人、已有群外人选、宿主自己负责或群内专员已接手的场景。另有条件模拟临时 Pi 在办、同伴已交接、引用培训台词、部分工具不可用以及用户改变决定。

### 先看宣传片群

G01 有六个分支。A 取自 2026-11-25 正式群的前七条公开消息，保留正文、顺序、回复关系、点名及附件名，成员 ID 使用本地别名。人员目录和工具可见范围按案例需要建模。B 在同一句话下增加一名群外视频专员。C 把需求改成宿主自己复用导出参数。D 让群内视频专员已明确接手，再回放同一句话。E 单看宿主建群后的第一句话。F 明确请 EggBot 保存群规范，后续制作仍由宿主负责。

A 的期望采用宿主事后说明的产品意图。还原当晚行为时，原版 EggBot 快读判了 `main`，主对话零工具调用结束。这个观察值没有写进模型输入。其余案例是为检验行为边界编写的场景，期望由本次设计拟定。部分分支接受多个合理反应。

### 回放方式

1. 从输入文件取一行，以 `id` 关联评分文件。每个分支独立初始化。消息依照 `sequence` 投递，`pending_message_ids` 指定本轮目标。此前发言构成历史；同一组其他分支和宿主后来的解释均不进入本轮上下文。
2. 使用对应版本的 EggBot 身份、角色提示词、快读提示词和主对话工具声明，按正式路径组装输入。`room.members` 是可见群成员。`active_sessions` 和 `peer_activities` 交由对应运行时投影处理，以正式路径实际可见范围为准。
3. `tool_fixture` 只交给内存工具适配层。`bot_directory` 模拟可查目录，包含本群 Bot 及可查的群外 Bot。`bundled_templates` 提供可查模板与激活状态。`faults` 只在对应操作发生时返回指定故障。普通操作按照实际工具契约返回结果，并同步更新目录、成员、文件及群消息。例中的 `lead`、`egg` 和 `bot-…` 为当前分支的别名。回放不需创建正式群或写入正式资料。
4. 让 EggBot 从快读运行到本轮自然结束，包括它自己发起的工具调用及回执。记录快读结果、工具参数、回执、公开发言及最终状态。对话中已有的主控和专员发言按材料回放。
5. 多个 `accepted_outcomes` 之间是“或”。每个结果中的 `required` 均需满足，`forbidden` 均不得发生。结合该题 `criterion`、目标身份与职责评分。新建角色可以用不同名称；复用已有角色须匹配同一个实例。交接需让目标成员获得本轮第一个具体任务。对于失败样本，检查 `failed_step`、`expected_new_bots_on_exit` 和真实回执。

### 判断什么

| 结果 | 可接受此结果的案例数¹ | 评分重点 |
|---|---:|---|
| N · 新建专职成员 | 310 | 先查可用成员。无合适人选时创建恰好一名职责匹配的 Bot，纳入当前群，并交接本轮的具体工作。 |
| R · 复用群外成员 | 289 | 找到指定的已有业务成员，把原实例加入当前群并交接首项工作。 |
| H · 向群内成员交接 | 82 | 把范围和首项工作交给已在群内的业务成员，群成员保持原样。 |
| S · 静默 | 395 | EggBot 无公共回复，无人员、文件或任务变更。只读观察可以接受。 |
| P · 回答或提出方案 | 129 | 通过群消息给出本题需要的说明、建议或对照，遵守用户保留的决定。 |
| Q · 澄清职责 | 55 | 向宿主询问会改变分工的具体问题。选项或措辞等价即可。 |
| B · 全局激活工作引擎 | 17 | 通过指定的 `bundled_id` 激活引擎，按该题的任务推进或说明所缺输入。 |
| E · 调用已启用的工作引擎 | 34 | 复用指定引擎，保持现有群成员。结合会话回执、业务交接或具体阻塞核对本轮进展。 |
| F · 如实报告工具阻塞 | 44 | 实际尝试应做的操作，根据已成功和失败的步骤向宿主准确说明进度。 |
| D · 只保存指定群文件 | 59 | 将要求的内容写入指定的群文件，人员及任务分工保持不变。 |

¹ 共 1,400 个决策点。其中 14 个接受两种相符反应，列合计为 1,414。静默题优先期望快读返回 `quiet`；若进入主对话后安静结束且无副作用，行为通过，另记一次额外唤醒。需要动作的题应进入 `main`。分别记录漏唤醒、唤醒后漏行动、错派、重复建人和未完成交接，有助于确定要改哪一层。

### 比较提示词版本

先用现版在开发集建立基线。相同分支重复回放时重置状态，保存每次结果和模型配置。重点看“该补位时实际补位”“已有成员时复用正确实例”和“该静默时误动人员”三个比例，保留分子和分母。迭代时按案例族看退步的分支。留出集按整群划分，同一群的反事实分支都在同一侧。群聊和字母分支用于检验特定行为，分支共享前文。比较两个版本时也应按群统计，避免把相近分支当成完全独立的真实对话。语料没有预填任何版本的成功率。
