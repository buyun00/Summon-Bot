# P5 · 群快读直转与跨群续办

2026-11-20 定稿。每个 Bot 的群快读①对收到的消息分别生成事实摘要，并依原话决定 `quiet`、`main` 或 `forward`。界面继续显示对输入事实的摘要。[P3 快读收件](3-5-p3-fast-read-and-main-output.md) · [P4 派工和交付](3-5-p4-execution-handoff-delivery.md)

## 什么消息可以直转

快读的候选来自本 Bot 的群主对话直接派出的未结案工作。候选来自当前原群，或来自显式向当前群开放的其他群。候选尾部带目标、等待摘要、引擎和当前输入方式。独立 Pi 的子会话只由它的父 Pi 管理。快读列候选时只读平台记录和本地 Pi 输入状态。

| 群消息和上下文 | 去向 |
| --- | --- |
| 单纯收悉，群里和内部都没有事项需要办理 | `quiet` |
| 给唯一在等文件名的工作补上文件名，目标和授权都延续原要求 | `forward`，附目标会话与有效的原生输入位置 |
| 两个工作都在等类似材料，用户没指明给哪个 | `main`，由②辨认归属 |
| 同时补件和改要求、叫停原工作、询问进度、要求公开解释 | 整条交 `main` |
| 提到其他群里尚未向本群开放的工作 | `main`，由②用 `find`、`read` 核实并联系原负责对话 |

## 按真实输入协议续投

Pi 支持给运行中的回合 `steer`，以及在其接受后续输入时 `next`。直转保留原消息、作者、引用与附件。Pi 能读取随该次输入共享且当前仍获准读取的事件或文件。Codex 和支持文本输入的 CLI 按原协议接收文本，普通自由文本问题可向指定 `reply` 位置送入原话。原生审批、固定选项、多题、表单及要求结构化输入的服务由②或宿主界面处理。发给外部引擎的附件交②准备。附件原址支线另行推进。

宿主提交前复核原群和续办群、结案状态、控制版本、原生输入位置及其接收格式。直转意图先落盘，一条群消息对于同一 Bot 使用固定调用编号。更新或重启后按已保存的调用恢复，目标失效交②处理。送达不确定时，②收到原消息、目标、原因及调用编号，可先读实际调用。异步结果和同步完成的结果都关联原派工回合。[快读运行时](../../../bot/src/runtime/fast-read.mjs) · [原生输入分类](../../../capabilities/platform/session-work.mjs)

## 跨群开放

派工时可声明 `allowed_followup_rooms`。此后由直接派生方用 `configure_session` 的 `add_followup_rooms` 和 `remove_followup_rooms` 开放或撤销续办。原群的 Bot 仍须能读取自己的工作。在已开放的群里，用户和同伴 Bot 的相关补充都可参与快读判断，补件人无需同时是原群成员。共享材料继续沿用实际接收方的可读范围。

未开放的跨群指代由②核实，群快读之间没有私下问答通道。续办不改变工作的父对话、原群和原提问。最终结果仍由原②验收并引用原提问发送。[执行控制](../../../capabilities/platform/executions.mjs) · [群消息与附件](../../../capabilities/chatroom/service.mjs)
