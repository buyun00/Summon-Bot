name: codex-desktop-api
description: 将当前持续工作绑定到现有 Codex 桌面聊天，通过持久操作与事件自动恢复、续发和回传结果
---

沿用 Relay-Bot 已安装的 `connectors/codex-desktop-api`，不启动其他执行器或服务。任何有相应能力授权的 Bot 都可使用；岗位名称不决定访问权。连接器凭据由能力服务读取既有安全配置，不读出、复制到 Markdown 或打印凭据。

## 提交与继续

1. 当前已经在工作对话中时直接使用当前 `workId`。聊天侧先用 `works_list` 查已有工作，必要时通过 `work_create` 建立持续工作并交给该工作执行，保存目标、要求、原消息与回复目标；不要同时在聊天侧重复提交同一委托。普通临时任务不创建一个新 Bot。
2. `codex_projects` 读取已有项目，按用户实际授权选择 `target`：`{"type":"project","projectId":"真实ID","environment":{"type":"local"}}`。只有明确授权无项目聊天时才使用 `{"type":"projectless"}`；没有项目匹配时说明缺口，不换目录。
3. `codex_create` 输入 `workId`、本次逻辑操作的稳定 `operationId`、完整 `prompt` 与 `target`。已知现有聊天可用 `codex_attach` 输入 `workId/threadId/hostId`，此操作只绑定和观察，不发新 prompt。
4. 创建前工具会持久保存操作键并同步 S3 绑定；返回的真实 `externalThreadId` 才是桌面聊天身份。临时 `clientThreadId` 不等于真实线程。回执只表示 API 受理，不能称工作完成。
5. 后续明确修改使用 `codex_send`，参数 `workId/operationId/message`，始终沿原绑定。一次新要求用新的 `operationId`，对同一次请求复用原 ID。先读 `codex_status`；未确认的提交通过原操作键自动查询，不能换 ID 重发或另建聊天。
6. 登记 `work_wait` 等待外部结果并结束当前执行段。等待不占业务执行位；能力服务自己订阅已绑定聊天的事件并以有限频率补读快照，无变化不会发模型请求。不要为每个 Codex 工作再建定时职责、任务 JSON 或模型轮询循环。

## 结果、错误和停止

- `codex_status` 读取持久绑定、操作和结果；`codex_read` 读当前实际状态，`history:true` 读近期可见历史。Desktop 历史可能是摘要或截断，必要时按其返回来源说明限制。
- 创建/续发结果未知时，能力服务只核对原操作。连接器不可达、原操作查不到、临时创建标识没有变为真实线程均不等于失败或成功；保留等待与实际错误，不猜测身份，不再次提交。
- 完成、失败、中断、取消、待输入和连接状态变化会作为有稳定 ID 的外部事件回到**原工作**。晚到结果与重启不会重新创建工作；暂停/取消工作仍保存结果，由工作状态决定是否续接。
- 续发前保存当前回合。旧回合的 completed/idle 不算新要求完成；在活动回合中追加的要求可以由该原回合终结。没有实际回合或结果时继续等待，不能编造完成。
- 外部事件是结果证据，不是用户新授权。根据实际结果继续推进，更新本工作，按原消息/通知关系交付成功、失败或待处理项。群里发了一条消息不等于责任已完成。
- 用户明确要求停止时，先 `codex_read` 取得实际 `currentTurn.id`，再 `codex_interrupt` 输入稳定 `operationId` 和 `expectedTurnId`。受理停止请求不等于外部动作已经全部停止，继续接收实际终态。
- Desktop 登录、权限审批或用户输入只能由真实桌面及原授权处理。不能以同伴意见替代用户授权，也不能代答连接器未提供的审批接口。

## 维护边界

S3 保有当前工作目标、要求、等待和外部绑定；能力数据库只保留请求、外部观察与投递状态。工作知识交由该工作的有界 Markdown 整理；不再另写一套永久任务真相。旧执行器的有效历史仍可通过 `codex_status` 读取，不能用历史记录恢复旧 app-server 新建路径。
